# AgentMemory Web

桌面版的配套 Chrome / Edge 扩展；也可以单独选择一个保存目录使用。在批量保存页选一个站点，点一次「批量保存」，把当前账号的网页版会话增量保存成 Markdown，写到你选择的目录。已接 DeepSeek、Kimi、腾讯元宝；ChatGPT 入口保留，真实站点尚未校准。

## 怎么加载

1. 打开 `chrome://extensions`，开启「开发者模式」。
2. 点「加载已解压的扩展程序」，选这个 `extension/` 目录。
3. 点扩展图标 →「打开批量保存」。
4. 在批量保存页选保存目录；如果选的是桌面端归档目录，勾上「这是桌面端归档目录」，文件会写到它下面的 `网页版/`。
5. 在同一个浏览器里登录要保存的站点，回到批量保存页选站点，点「批量保存」。

批量标签页会在后台打开，不抢当前页面；进度、跳过、空会话和失败项都在批量保存页里看。失败项会保留在页面上，可以再点一次批量重试。

## 写到哪里

- 独立目录：`<保存目录>/<站点>/<日期>-<标题>-<标识>.md`
- 桌面端归档目录：`<归档目录>/网页版/<站点>/<日期>-<标题>-<标识>.md`

站点目录为 `DeepSeek`、`Kimi`、`腾讯元宝`、`ChatGPT`。Markdown 结构与桌面端归档一致：标题、渠道 / 项目 / 会话 / 开始 / 消息 / 来源，正文放在动态围栏里。增量索引在 `chrome.storage.local`；目录句柄在 IndexedDB。插件不读写桌面端的 `index.json`、`census.json`、`runs.jsonl`。

## 取数方式

| 站点 | 会话列表 | 消息详情 | 鉴权 |
|---|---|---|---|
| DeepSeek | `GET /api/v0/chat_session/fetch_page` | `GET /api/v0/chat/history_messages?chat_session_id=…` | 页面 `localStorage.userToken` |
| Kimi | `POST /apiv2/kimi.gateway.feed.v1.FeedService/ListFeeds` | `POST …/ChatService/GetChat` + `POST …/ChatService/ListMessages` | 页面 `localStorage.access_token` |
| 腾讯元宝 | `POST /api/user/agent/conversation/list` | `POST /api/user/agent/conversation/v1/detail` | 浏览器 cookie |
| ChatGPT | 同源接口优先，DOM 兜底 | 同源接口优先，失败时逐条打开会话解析 | 浏览器 cookie |

DeepSeek、Kimi、腾讯元宝在站点页面里调用它自己的同源查询接口；ChatGPT 同源接口优先，失败时退回页面解析。登录令牌和 cookie 只在站点页面上下文里使用：不保存、不写日志、不传往扩展页或其他站点。

## 真实站点验证清单

真实站点验证需要已登录的浏览器，本轮未执行；以下步骤交给能登录三家站点的验证者。DeepSeek 已用真实响应校准；Kimi、腾讯元宝的字段与分页仍待真实样本确认。

### 准备

1. 在 Chrome / Edge 加载 `extension/`，打开批量保存页，选一个**空目录**当保存目录。
2. 在同一浏览器登录 DeepSeek、Kimi、腾讯元宝。不需要导出 cookie 或令牌。
3. 三家都跑完后对照本文「已知边界」判断是适配器问题还是站点改版。

### 每家站点重复

1. 选站点，点「批量保存」。结束后记录：会话总数是否与网页侧边栏大致一致，保存 / 跳过 / 空会话 / 失败各多少，失败项的错误文案。
2. 打开一份新生成的 Markdown，对照网页检查：标题、会话 URL、角色顺序、正文、思考块、参考来源编号。Kimi / 元宝的思考应转为 `> **思考过程**` 引用块，引用标记应变成 `[n]` 并附「参考来源」。
3. 不新增消息，再点一次「批量保存」：应全部跳过，文件数量不变。
4. 在网页里给一个会话补 1 轮对话，再保存：应只更新该会话的文件，消息数增加，旧内容不重复。
5. 在网页里改一个会话标题，再保存：应只留下一份文件，文件名跟着标题变化。
6. 在批量过程中点「停止」：不再新增文件，结束时显示「已停止」。
7. 勾选「这是桌面端归档目录」再保存：新文件应落在 `<归档目录>/网页版/<站点>/`。

### 记录结果

每家站点给一份简短结果：通过 / 不通过的步骤、页面上的错误文案、失败会话的标题。接口字段对不上时，附一份**去掉 cookie、token 和消息正文**的响应字段结构（字段名与类型即可），不要提交完整原始响应。

### 隐私核对

- Network 面板里只应有站点自身域名的请求，没有扩展页或第三方上传。
- `chrome.storage.local` 只应有 `webIndex` 和 `webSettings`，不含令牌；IndexedDB 只存目录句柄。
- Console 不应出现消息正文或令牌。
- 插件不拦截、不改写网页自身的请求 / 响应。

## 已知边界

- **接口字段待真实样本校准**：DeepSeek 已用真实响应校准；Kimi、腾讯元宝按公开接口事实与参考实现核对，已有合成夹具测试，仍需真实登录后的响应确认。
- **ChatGPT**：同源接口优先、DOM 兜底已接，真实站点尚未校准。
- **手动批量**：不监听页面变化，不做后台定时；不点「批量保存」就不写盘。
- **仅本地**：第一版不做 Git / 网盘备份。
- **目录授权**：浏览器重启或升级后可能需要重新点一次「允许」；失效时批量保存页会提示，已保存的文件不丢。
- **站点限制**：批量读取可能触发站点限流或风控；失败按会话记录，不会中断整批。

## 隐私

插件只读当前账号的会话内容；登录令牌只在站点页面内存里用于同源查询接口，不保存、不写日志、不传往扩展页或其他站点；不拦截或改写网页自身的请求 / 响应；不上传内容。写盘只发生在你选择的目录。
